# 외부 서비스 연결 목록과 실제 운영 전환 안내

이 사이트는 외부 서비스가 연결되지 않아도 **테스트 모드**로 모든 흐름을 시험할 수 있습니다.
연결 전에는 실제 결제·메일 발송이 일어나지 않고, 화면에도 그렇게 표시됩니다.
연결 상태는 관리자 화면 **현황·연결 상태** 탭에서 확인합니다.

## 1. 연결 목록

| 구분 | 서비스 | 필요한 것 | 설정 위치 | 연결 전 동작 |
|---|---|---|---|---|
| 결제 (A안, 초기 운영) | 결제 링크 (결제서비스의 링크 결제 기능) | 과정별 결제 링크 URL | 관리자 › 과정 › 결제 링크, `.env` `PAYMENT_MODE=link` | — |
| 결제 (B안, 정식 운영) | 토스페이먼츠 | 가맹 계약, 클라이언트 키, 시크릿 키, 웹훅 등록 | `.env` `PAYMENT_MODE=toss`, `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY` | 테스트 모드 |
| 결제 (B안 대안) | 엑심베이 | 가맹 계약, MID, API 키, **계약 시 받는 연동 문서** | `.env` `PAYMENT_MODE=eximbay` … | 구현 대기 (아래 참고) |
| 이메일 | Resend (또는 동급 서비스) | API 키, 발신 주소, 발신 도메인 인증(SPF/DKIM) | `.env` `EMAIL_PROVIDER=resend`, `EMAIL_FROM`, `RESEND_API_KEY` | 발송함에 ‘미발송(서비스 미연결)’으로 기록 |
| 화상수업 | Zoom, Google Meet 등 | 회차별 회의 링크 | 관리자 › 개설반·시간표 | 학습자 화면에 ‘링크는 수업 전 등록’ 표시 |
| 학습 자료 저장소 | 접근 제한 가능한 저장소 | 사용 권한이 확보된 자료의 URL | 관리자 › 자료·복습 문제 | — |
| 도메인·HTTPS | 도메인 등록 + 호스팅 | 도메인, TLS 인증서 | `.env` `PUBLIC_BASE_URL=https://…`, `NODE_ENV=production` | — |
| 서버·DB | Node.js 22.5 이상이 실행되는 서버 | 영구 디스크(SQLite 파일), 백업 | `.env` `DATABASE_PATH` | — |

## 2. 결제서비스 선택 기준 (계약 전에 직접 확인)

토스페이먼츠와 엑심베이 중 하나를 고르기 전에 아래를 확인하세요.
이 문서는 **확인할 질문**만 정리합니다. 수수료·조건은 각 회사에 직접 문의해 최신 내용을 받아야 합니다.

| 확인 항목 | 질문 |
|---|---|
| 운영 사업자 소재 국가 | 한국 사업자인가요? 해외 법인인가요? (결제서비스마다 가입 가능한 사업자 국가가 다릅니다) |
| 교육 서비스 입점 | 온라인 교육(비대면 강의) 업종으로 가입할 수 있나요? 심사 서류는 무엇인가요? |
| 해외 발급 카드 | 해외 발급 Visa/Master/JCB 등을 받을 수 있나요? 별도 계약(해외카드·해외결제)이 필요한가요? |
| 국내 발급 카드 | 국내 카드와 해외 카드를 한 계약으로 받을 수 있나요? |
| 지원 통화 | 원화(KRW)만 청구하나요, 달러(USD) 등 외화 청구도 되나요? 학습자 카드사 환전 수수료 안내 방법은? |
| 수수료 | 국내 카드·해외 카드 수수료율, 환불 시 수수료 처리 |
| 정산 | 정산 주기, 정산 통화, 정산 계좌(원화/외화), 보증보험·예치금 필요 여부 |
| 환불 | API 부분 환불 지원 여부, 환불 가능 기간 |
| 결제 링크 | 링크 결제 기능이 있는지, 주문번호(참조값)를 링크에 넘길 수 있는지 |
| 웹훅 | 결제 상태 변경 통지(웹훅) 제공 여부 |

> 사이트는 과정마다 결제 통화를 고를 수 있게 되어 있습니다. **계약된 통화만** 선택하세요.

## 3. 결제 연동 구조 (구현된 내용)

### 공통 안전장치
- 카드번호·보안코드는 **이 사이트가 받지도 저장하지도 않습니다**. 결제는 결제서비스 결제창에서만 이뤄집니다.
- **시크릿 키는 서버 `.env`에만** 둡니다. 브라우저에는 공개용 클라이언트 키만 전달됩니다.
- 결제창에서 돌아왔다는 사실만으로 완료 처리하지 않습니다. 서버가 **주문 금액과 비교 → 결제서비스 승인 API 호출 → 응답 금액·통화 재확인** 후에만 `결제 완료`로 바꿉니다.
- 금액은 서버가 과정 가격으로 정하며, 브라우저가 보낸 금액이 다르면 즉시 실패 처리하고 기록을 남깁니다.
- 같은 신청에서 버튼을 여러 번 눌러도 주문은 하나만 생깁니다(멱등키). 같은 승인·웹훅이 여러 번 와도 수강 등록은 한 번만 됩니다.
- 결제 시도마다 결제사용 주문번호(`주문번호-시도횟수`)를 새로 발급해, 실패 후 재시도가 막히지 않습니다. 실패해도 신청 정보는 유지됩니다.
- 주문 상태: 결제 대기 / 결제 확인 대기(링크) / 결제 완료 / 결제 실패 / 시간 만료 / 취소 / 부분 환불 / 전체 환불.

### 정원과 결제 중 좌석
- 결제를 시작하면 좌석을 **15분**(`SEAT_HOLD_MINUTES`) 동안 임시 확보합니다. 그동안 다른 사람은 그 좌석을 신청할 수 없습니다.
- 시간이 지나면 자동으로 풀립니다. 늦게 돌아왔을 때 좌석이 없으면 **승인 요청 자체를 하지 않아** 청구되지 않습니다.
- 링크 결제에서 학습자가 ‘결제를 마쳤어요’를 누르면 72시간 동안 좌석을 유지합니다.
- 이미 돈이 결제된 뒤(웹훅·수동 확인) 정원이 넘친 경우에는 수강 등록 후 주문에 `검토 필요(over_capacity)`를 표시해 관리자가 판단합니다.

### A안 — 결제 링크 (초기 운영)
1. `.env`에 `PAYMENT_MODE=link`.
2. 결제서비스에서 과정별 결제 링크를 만들어 관리자 › 과정 › 결제 링크에 등록합니다.
3. 학습자가 주문을 확정하고 ‘결제하기’를 누르면 링크가 열리고, 주문번호를 결제 메모에 적도록 안내합니다. (`?orderNo=` 파라미터도 함께 붙습니다. 결제서비스가 지원하면 자동 연결됩니다.)
4. 학습자가 ‘결제를 마쳤어요’ → 주문 상태 `결제 확인 대기`. **이것만으로 수강 등록되지 않습니다.**
5. 관리자가 결제서비스 관리 화면에서 입금을 확인한 뒤 관리자 › 주문·결제에서 **거래번호와 확인 금액**을 입력합니다. 금액이 주문과 같아야 수강이 등록됩니다.
6. 환불은 결제서비스에서 먼저 환불한 뒤 관리자 화면에 근거를 입력해 기록합니다.

### B안 — 사이트 내 결제 (토스페이먼츠)
1. `.env`: `PAYMENT_MODE=toss`, `TOSS_CLIENT_KEY`, `TOSS_SECRET_KEY`, `PUBLIC_BASE_URL=https://운영도메인`.
2. 토스페이먼츠 개발자센터에서 **웹훅 URL**을 `https://운영도메인/api/payments/webhook/toss`로 등록합니다. 웹훅 본문은 신뢰하지 않고 서버가 토스 결제 조회 API로 다시 확인합니다.
3. 서버 재시작 후 관리자 › 현황에서 ‘토스페이먼츠: 테스트 키/라이브 키’ 표시를 확인합니다. 키가 `test_`로 시작하면 실결제가 아님을 화면에 계속 표시합니다.
4. 결제 흐름: 서버에서 주문번호·금액 생성 → 토스 결제창(v2 SDK) → 성공 URL 복귀 → 서버 승인 API(`/v1/payments/confirm`) → 금액 검증 → 수강 등록.
5. 환불: 관리자 승인 시 서버가 토스 취소 API(`/v1/payments/{paymentKey}/cancel`)로 전체·부분 취소하고 결과를 주문에 반영합니다.
6. 해외 카드·외화 결제는 토스 쪽 별도 계약 범위를 확인한 뒤 과정 통화를 설정하세요.

### 엑심베이
- 엑심베이는 계약 후 제공되는 연동 문서(요청 형식, 서명 방식, 승인·조회·취소 API)에 맞춰 구현해야 합니다.
- 문서 없이 추측으로 결제 요청을 만들지 않도록 `server/payments.js`의 `eximbayProvider`는 **‘구현 대기’** 상태입니다. `PAYMENT_MODE=eximbay`로 두면 결제가 열리지 않습니다.
- 구현 시 같은 인터페이스(`checkout / confirm / fetch / cancel`)만 채우면 주문·정원·환불·기록 로직은 그대로 사용됩니다.

## 4. 이메일 안내 구조

| 시점 | 템플릿 | 받는 사람 |
|---|---|---|
| 회원가입 | `signup` | 학습자 |
| 비밀번호 재설정 | `password_reset` (링크는 발송함에 남기지 않음) | 학습자 |
| 수강 신청(주문 생성) | `order_created` | 학습자 |
| 결제 완료·수강 등록 | `payment_paid` | 학습자 |
| 수업 일정 안내 | `schedule_notice` (관리자 › 개설반 › 안내 메일) | 해당 반 수강생 |
| 취소·환불 결과 | `refund_result` | 학습자 |
| 문의 답변 | `inquiry_reply` | 문의자 |

발송 서비스가 연결되지 않으면 모든 메일은 `미발송(서비스 미연결)`으로 기록되며, 학습자 화면에도 “메일이 발송되지 않았습니다”라고 표시합니다.

## 5. 실제 운영 전 체크 항목

관리자 › 현황 하단에도 같은 항목이 자동 점검됩니다(수동 확인 항목은 체크박스).

**사업자·법적 정보**
- [ ] 운영기관명, 대표자, 사업자등록번호, 주소, 문의 이메일, 연락처 입력
- [ ] 통신판매업 신고 해당 여부 확인 및 신고번호 입력
- [ ] 이용약관(한·영) 확정·게시 — 비어 있으면 결제가 열리지 않음
- [ ] 개인정보 처리방침(한·영) + 개인정보 보호책임자 확정·게시 — 해외 학습자 개인정보 처리(국외 이전 등) 포함 여부 검토
- [ ] 과정별 취소·환불 기준 확정 — 적용 규정을 확인한 뒤 입력 (사이트는 기준을 임의로 만들지 않음)

**결제**
- [ ] 결제서비스 선택(2장 기준) 및 가맹 계약
- [ ] 정산 계좌 등록
- [ ] 운영 키 `.env` 입력, 웹훅 URL 등록
- [ ] 소액 실결제 → 승인 → 환불까지 1회 시험

**콘텐츠**
- [ ] 강사 소개·자격·경력 입력 (자격증 사본은 개인정보 가림)
- [ ] 과정별 수강료·통화·수업 횟수·회당 시간 확정
- [ ] 개설반·시간표·화상수업 링크 등록
- [ ] 학습 자료는 사용 권한 확보분만 등록

**인프라·보안**
- [ ] 도메인 연결, HTTPS, `NODE_ENV=production`, `PUBLIC_BASE_URL`
- [ ] 이메일 발송 서비스 연결, 발신 도메인 인증
- [ ] 관리자 계정 2단계 인증 설정, `ADMIN_REQUIRE_MFA=true`
- [ ] DB 파일 정기 백업 (예: 매일 `data/korean-together.db` 복사본 외부 보관)
